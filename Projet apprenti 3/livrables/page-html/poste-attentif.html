01 — Pourquoi ce projet ?

Prévenir localement. Détecter sur le réseau.

Risque physique

Une session laissée ouverte

Un agent quitte son bureau sans verrouiller Windows. Un radar de présence peut réduire le délai pendant lequel la session reste accessible.

Le tuteur a confirmé l'existence d'oublis de verrouillage ; la performance du dispositif reste à mesurer.

Risque réseau

Une activité qui passe inaperçue

Un équipement leurre simule un service non utilisé : une connexion vers ce service fournit un signal supplémentaire à examiner.

L'ANSSI a publié en septembre 2026 un rapport sur des faiblesses de détection à la DGFiP. Cela ne démontre pas qu'un leurre ESP32 aurait empêché les incidents.

Problématique : dans quelle mesure un prototype embarqué peut-il améliorer la prévention des accès locaux non autorisés et compléter la détection d'interactions réseau inhabituelles, avec un minimum de fausses alertes ?
02 — Architecture

Deux fonctions indépendantes, une supervision commune.

A / Prévention

LD2410 + ESP32

Le radar estime la présence dans une zone définie. L'ESP32 envoie des messages authentifiés par HMAC à un service du poste, qui déclenche le verrouillage de Windows.

B / Détection

ESP32 + W5500

Le second boîtier présente un service HTTP imitant une imprimante. Il journalise uniquement les interactions techniques avec ce service, sans recevoir de données métier.

C / Exploitation

Windows + Ubuntu

Un PC Windows de test et un serveur Ubuntu de laboratoire permettent les scripts PowerShell, le transport sécurisé des événements, les captures Wireshark et les alertes.

Frontière de confiance : le verrouillage doit continuer même si Ubuntu ou le réseau sont indisponibles. Une interaction avec le leurre ne doit jamais entraîner le verrouillage d'un poste.
03 — Démonstration interactive

Une journée de Martine, en laboratoire.

Choisis un événement. Le résultat affiché est une simulation de principe, pas une mesure obtenue avec le matériel.

Session Windows : verrouillée

Le radar détecte une absence suffisamment longue. Le poste valide le message et verrouille localement la session.

Le radar ne permet pas d'identifier l'utilisateur. Les seuils et délais doivent être étalonnés et testés.

[10:15:03] Windows  verrouillage local
[10:15:04] Ubuntu   événement reçu

Version 1 — démonstrateur minimal

Radar, ESP32, verrouillage Windows local et leurre HTTP simple, un serveur Ubuntu, essais reproductibles.

Version 2 — robustesse et évaluation

HMAC/compteur, gestion des pannes, authentification de l'API, filtrage des alertes, campagnes de tests et indicateurs.

05 — Périmètre et éthique

Pas de surveillance des agents. Pas de réseau réel.

Ce que le projet ne fait pas

Pas de caméra, pas de reconnaissance des personnes, pas d'enregistrement des durées d'absence, pas de capture de mots de passe, pas d'attaque contre un réseau tiers. Il n'affirme pas détecter toutes les intrusions.

Conditions d'un éventuel pilote

Autorisation écrite du service, validation sécurité et protection des données, conformité des équipements USB/Ethernet, qualification des flux réseau et des durées de conservation.
